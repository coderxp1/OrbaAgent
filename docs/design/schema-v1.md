## 1. Architectural Principles & Ownership Boundaries

This design document specifies the complete relational schema for OrbaAgent. It establishes strict boundaries between authentication tables generated by Better Auth and core domain tables authored for OrbaAgent, defines a dual-layer tenancy model (Application + Row-Level Security), and formalizes data lifecycle rules.

### 1.1 Better Auth ↔ Drizzle Ownership Boundary

To eliminate migration conflicts and schema divergence, tables are segregated into two distinct ownership domains:

```
┌────────────────────────────────────────────────────────┐
│                   PostgreSQL Database                  │
├────────────────────────────┬───────────────────────────┤
│   Better Auth Domain       │   OrbaAgent Domain        │
│   (Generated / Managed     │   (Hand-Authored Drizzle  │
│    by @better-auth/cli)    │    Domain Migrations)     │
├────────────────────────────┼───────────────────────────┤
│ - user                     │ - projects                │
│ - session                  │ - agents                  │
│ - account                  │ - runs                    │
│ - verification             │ - run_steps               │
│ - organization             │ - files                   │
│ - member                   │ - computer_sandboxes      │
│ - invitation               │ - model_providers         │
│ - apiKey                   │ - provider_credentials    │
│ - twoFactor                │ - audit_logs              │
└────────────────────────────┴───────────────────────────┘
```

#### Ownership Rules:
1. **Never Hand-Edit Better Auth Schemas:** Tables in the Better Auth domain are managed exclusively through `npx @better-auth/cli generate` and Better Auth plugins (`organization`, `twoFactor`, `bearer` from `better-auth/plugins`, and `apiKey` from `@better-auth/api-key`). Hand-modifying these generated files will cause upstream migration generator divergence.
2. **Domain Separation:** Better Auth tables reside in `src/db/schema/auth.ts`; OrbaAgent domain tables reside in `src/db/schema/domain.ts`. Both are exported via `src/db/schema/index.ts`.
3. **Foreign Keys Across Domains:** OrbaAgent domain tables reference `organization.id` and `user.id` using standard PostgreSQL foreign key constraints with `ON DELETE RESTRICT` or `ON DELETE CASCADE`.

## 2. Multi-Tenancy & Isolation Architecture

Multi-tenancy in OrbaAgent uses an **organization-scoped shared-database architecture** enforced with **Defense-in-Depth**:

### 2.1 Layer 1: Application-Level Tenant Scoping
Every domain query executed by the Fastify API or background services must explicitly filter by `organization_id` derived from the verified session or API key context:
```typescript
const orgId = request.tenantContext.organizationId;
const result = await db
  .select()
  .from(agents)
  .where(and(eq(agents.organizationId, orgId), isNull(agents.deletedAt)));
```

### 2.2 Layer 2: Database-Level Row-Level Security (RLS)
As a fail-safe against missed application-level `where` clauses, Row-Level Security is enabled on every table containing `organization_id`:

```sql
-- Enable RLS on domain tables
ALTER TABLE projects ENABLE ROW LEVEL SECURITY;
ALTER TABLE agents ENABLE ROW LEVEL SECURITY;
ALTER TABLE runs ENABLE ROW LEVEL SECURITY;
ALTER TABLE files ENABLE ROW LEVEL SECURITY;
ALTER TABLE computer_sandboxes ENABLE ROW LEVEL SECURITY;
ALTER TABLE provider_credentials ENABLE ROW LEVEL SECURITY;
ALTER TABLE audit_logs ENABLE ROW LEVEL SECURITY;

-- Tenant isolation policy pattern
CREATE POLICY tenant_isolation_policy ON <table_name>
  FOR ALL
  USING (organization_id = NULLIF(current_setting('app.organization_id', true), '')::uuid);
```

#### Connection-Pool Implication & Transaction Scoping:
Because Fastify and Drizzle share a connection pool, setting session-level state via `SET app.organization_id = ...` would poison the connection for subsequent requests handled by the same connection pool worker.

**Mandatory Pattern:** Tenant context must be set using `SET LOCAL` strictly within an interactive transaction:
```sql
BEGIN;
SET LOCAL app.organization_id = '0191c49b-7320-7f23-8c43-85f26938a1a0';
-- Execute tenant queries safely
COMMIT; -- Context automatically clears on COMMIT or ROLLBACK
```

## 3. Data Lifecycle & Deletion Strategy

| Strategy | Applicable Tables | Mechanism | Rationale |
| :--- | :--- | :--- | :--- |
| **Soft-Delete** | `organizations`, `users`, `projects`, `agents`, `files` | `deleted_at TIMESTAMPTZ DEFAULT NULL` | Enables user undo, maintains referential integrity, supports regulatory retention. Unique indexes use partial filters (`WHERE deleted_at IS NULL`). |
| **Hard-Delete** | `sessions`, `verifications` | SQL `DELETE` | Prevents token reuse; expired authentication secrets must be completely purged from disk. |
| **Explicit Revocation** | `api_keys`, `provider_credentials` | `revoked_at TIMESTAMPTZ DEFAULT NULL` | Preserves attribution in audit logs for revoked keys; revoked keys are immediately rejected during auth lookup. |
| **Immutable Append-Only** | `audit_logs`, `runs`, `run_steps` | Enforced via PostgreSQL triggers & DB roles | Compliance, non-repudiation, and audit integrity. Updates and deletions are strictly blocked. |

## 4. Key Security Designs

### 4.1 Session Token Security & Hashing
- **Better Auth Default:** Better Auth uses high-entropy random tokens and indexes `session.token` directly for high-throughput lookups.
- **Risk:** If a database read replica is compromised or SQL injection occurs, plaintext tokens grant immediate session hijacking.
- **Mitigation Architecture:**
  1. **Short Lifetimes:** Maximum 7-day session lifetime with 24-hour rolling inactivity expiration.
  2. **Transport & Storage Encryption:** Enforced TLS 1.3 in transit and PostgreSQL disk encryption at rest.
  3. **Token Hashing Migration Path:** Better Auth adapter lifecycle hooks will be used in Phase 1 to store `SHA-256(token)` in `token_hash` for lookup, ensuring plaintext tokens exist only on the client.

### 4.2 API Keys: Scopes & Service Keys
- **Org-Level vs. User-Level:**
  - `user_id` is **nullable**. When `user_id IS NULL`, the key is an **Organization Service Key** (for CI/CD, cron jobs, and headless infrastructure).
  - When `user_id` is populated, the key is a **Personal Access Token** bound to that user's membership and permission ceiling.
- **Scope Vocabulary:**
  ```text
  agents:read       - View agent configurations and prompts
  agents:write      - Create and edit agents
  agents:run        - Trigger execution runs
  runs:read         - Inspect runs and execution logs
  runs:create       - Start new agent runs
  runs:cancel       - Cancel active runs
  files:read        - Download artifacts and outputs
  files:write       - Upload files to project storage
  files:delete      - Remove uploaded files
  sandboxes:view    - Request short-lived live-view tokens
  sandboxes:control - Send input events to sandboxes
  org:read          - View organization details and members
  org:admin         - Manage billing, members, and credentials
  ```
- **Cryptographic Storage:**
  - `key_prefix`: Public 8-character prefix (e.g., `orba_live_7a3f89bc_...`) for routing and identification.
  - `key_hash`: SHA-256 hash of the complete secret token. The raw secret is displayed to the user exactly once upon generation.

### 4.3 `computer_sandboxes` Security (Reference: ADR-002)
- **Zero URL Persistence:** **Never persist live URLs (e.g. `vnc_url` or `desktop_url`) in the database.** Storing live URLs turns database columns into bearer credentials.
- **Tokenized Live Access:** Live desktop and VNC streams are minted on-demand per request by `services/computer-runtime` as short-lived (60-second) HMAC-signed tokens verified at the WebSocket gateway.

### 4.4 Envelope Encryption for BYO-Key Provider Credentials
- Programmatic API keys for external model providers (Anthropic, OpenAI, Google) stored in `provider_credentials` are encrypted using **AES-256-GCM envelope encryption**.
- Plaintext keys are never written to disk or logs. The database stores:
  - `encrypted_api_key`: Hex/base64 ciphertext + initialization vector (IV) + authentication tag.
  - `key_version`: Identifier of the master Key Encryption Key (KEK) managed in environment secrets / KMS.

### 4.5 Append-Only Enforcement for `audit_logs`
Enforced with two independent layers:
1. **PostgreSQL Role Privileges:**
   ```sql
   REVOKE UPDATE, DELETE ON audit_logs FROM orba_app;
   GRANT SELECT, INSERT ON audit_logs TO orba_app;
   ```
2. **Database Trigger Guard:**
   ```sql
   CREATE OR REPLACE FUNCTION reject_audit_log_mutation()
   RETURNS TRIGGER AS $$
   BEGIN
     RAISE EXCEPTION 'Table audit_logs is strictly append-only. UPDATE and DELETE are prohibited.'
       USING ERRCODE = 'integrity_constraint_violation';
   END;
   $$ LANGUAGE plpgsql;

   CREATE TRIGGER trg_audit_logs_immutable
     BEFORE UPDATE OR DELETE ON audit_logs
     FOR EACH ROW EXECUTE FUNCTION reject_audit_log_mutation();
   ```

## 5. Entity Relationship & Schema Definitions

### 5.1 Primary Key Strategy
All tables use **UUIDv7** primary keys. UUIDv7 combines Unix millisecond timestamps with cryptographically random bits, providing:
- Time-ordered monotonic sorting (drastically reducing B-Tree page fragmentation compared to random UUIDv4).
- Safe client-side and application-side ID generation before inserting.
- Native PostgreSQL `uuid` type efficiency (16 bytes).

### 5.2 Domain Table Specifications

#### Table: `projects`
Logical workspace grouping agents, runs, files, and sandboxes.
```sql
CREATE TABLE projects (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
  name VARCHAR(255) NOT NULL,
  slug VARCHAR(255) NOT NULL,
  description TEXT,
  created_by UUID REFERENCES "user"(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at TIMESTAMPTZ,
  CONSTRAINT uq_projects_org_slug UNIQUE (organization_id, slug)
);

CREATE INDEX idx_projects_org ON projects(organization_id) WHERE deleted_at IS NULL;
```

#### Table: `agents`
Configured autonomous agent templates and runtime definitions.
```sql
CREATE TABLE agents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
  project_id UUID REFERENCES projects(id) ON DELETE SET NULL,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  model VARCHAR(128) NOT NULL, -- e.g. 'claude-3-7-sonnet', 'gpt-4o'
  system_prompt TEXT NOT NULL,
  config JSONB NOT NULL DEFAULT '{}'::jsonb, -- temperature, max_tokens, tool config
  created_by UUID REFERENCES "user"(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at TIMESTAMPTZ
);

CREATE INDEX idx_agents_org ON agents(organization_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_agents_project ON agents(project_id) WHERE deleted_at IS NULL;
```

#### Table: `runs`
Execution instances of agents. Supports hierarchical multi-agent trees via `parent_run_id`.
```sql
CREATE TYPE run_status AS ENUM ('queued', 'running', 'completed', 'failed', 'cancelled', 'timed_out');

CREATE TABLE runs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
  project_id UUID REFERENCES projects(id) ON DELETE SET NULL,
  agent_id UUID NOT NULL REFERENCES agents(id) ON DELETE RESTRICT,
  parent_run_id UUID REFERENCES runs(id) ON DELETE CASCADE, -- Hierarchical sub-agent runs
  status run_status NOT NULL DEFAULT 'queued',
  input JSONB NOT NULL,
  output JSONB,
  error JSONB,
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_runs_org_created ON runs(organization_id, created_at DESC);
CREATE INDEX idx_runs_agent ON runs(agent_id, created_at DESC);
CREATE INDEX idx_runs_parent ON runs(parent_run_id) WHERE parent_run_id IS NOT NULL;
CREATE INDEX idx_runs_status ON runs(organization_id, status);
```

#### Table: `run_steps`
Individual execution steps (thoughts, tool calls, observations) feeding the model gateway ledger and billing.
```sql
CREATE TYPE step_type AS ENUM ('thought', 'tool_call', 'observation', 'response');

CREATE TABLE run_steps (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  run_id UUID NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
  step_number INTEGER NOT NULL,
  type step_type NOT NULL,
  tool_name VARCHAR(128),
  input JSONB,
  output JSONB,
  token_usage JSONB, -- { provider, model, input_tokens, output_tokens, cached_tokens, cost_usd }
  duration_ms INTEGER,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT uq_run_steps_sequence UNIQUE (run_id, step_number)
);

CREATE INDEX idx_run_steps_run ON run_steps(run_id, step_number ASC);
```

#### Table: `files`
Object storage metadata tracking artifacts stored in MinIO/S3.
```sql
CREATE TABLE files (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
  project_id UUID REFERENCES projects(id) ON DELETE SET NULL,
  run_id UUID REFERENCES runs(id) ON DELETE SET NULL,
  bucket VARCHAR(63) NOT NULL,
  key TEXT NOT NULL,
  size_bytes BIGINT NOT NULL,
  mime_type VARCHAR(127) NOT NULL,
  sha256 CHAR(64) NOT NULL,
  uploaded_by UUID REFERENCES "user"(id) ON DELETE SET NULL,
  metadata JSONB NOT NULL DEFAULT '{}'::jsonb,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at TIMESTAMPTZ,
  CONSTRAINT uq_files_org_bucket_key UNIQUE (organization_id, bucket, key)
);

CREATE INDEX idx_files_org ON files(organization_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_files_run ON files(run_id) WHERE run_id IS NOT NULL;
```

#### Table: `computer_sandboxes`
Ephemeral desktop sandbox instances managed by `services/computer-runtime` (per ADR-002).
```sql
CREATE TYPE sandbox_state AS ENUM ('provisioning', 'running', 'paused', 'stopped', 'terminated', 'failed');
CREATE TYPE sandbox_runtime AS ENUM ('docker', 'gvisor', 'firecracker');

CREATE TABLE computer_sandboxes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
  run_id UUID NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
  container_id VARCHAR(128) NOT NULL,
  runtime sandbox_runtime NOT NULL DEFAULT 'docker',
  resource_profile JSONB NOT NULL, -- { cpus: 2, ram_mb: 2048, disk_gb: 10 }
  network_policy_id VARCHAR(64) NOT NULL DEFAULT 'egress-restricted',
  state sandbox_state NOT NULL DEFAULT 'provisioning',
  started_at TIMESTAMPTZ,
  stopped_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_sandboxes_org_state ON computer_sandboxes(organization_id, state);
CREATE INDEX idx_sandboxes_run ON computer_sandboxes(run_id);
```

#### Table: `model_providers` & `provider_credentials`
Catalog of supported LLM backends and tenant-specific encrypted BYO keys.
```sql
CREATE TABLE model_providers (
  id VARCHAR(64) PRIMARY KEY, -- e.g. 'anthropic', 'openai', 'deepseek', 'google'
  name VARCHAR(128) NOT NULL,
  api_base_url TEXT NOT NULL,
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE provider_credentials (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
  provider_id VARCHAR(64) NOT NULL REFERENCES model_providers(id) ON DELETE RESTRICT,
  key_identifier VARCHAR(64) NOT NULL, -- Human reference (e.g. 'Production Claude Key')
  encrypted_api_key TEXT NOT NULL, -- Envelope-encrypted payload (AES-256-GCM ciphertext:iv:tag)
  key_version INTEGER NOT NULL DEFAULT 1,
  created_by UUID REFERENCES "user"(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  revoked_at TIMESTAMPTZ,
  CONSTRAINT uq_provider_credentials_org_provider UNIQUE (organization_id, provider_id, key_identifier)
);

CREATE INDEX idx_provider_credentials_org ON provider_credentials(organization_id) WHERE revoked_at IS NULL;
```

#### Table: `audit_logs` (Partitioned by Month)
Immutable, append-only security and operational audit trail.
```sql
CREATE TABLE audit_logs (
  id UUID DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
  request_id VARCHAR(64), -- Traces to Fastify HTTP request
  session_id VARCHAR(64), -- Traces to user session or API key
  actor_type VARCHAR(32) NOT NULL, -- 'user', 'api_key', 'system'
  actor_id VARCHAR(64) NOT NULL,
  action VARCHAR(128) NOT NULL, -- e.g. 'agent.create', 'run.execute', 'key.revoke'
  target_type VARCHAR(64) NOT NULL, -- 'agent', 'run', 'file', 'membership'
  target_id VARCHAR(64) NOT NULL,
  diff JSONB, -- { before: {...}, after: {...} }
  ip_address INET,
  user_agent TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (id, created_at)
) PARTITION BY RANGE (created_at);

-- Monthly partition examples
CREATE TABLE audit_logs_y2026m09 PARTITION OF audit_logs
  FOR VALUES FROM ('2026-09-01 00:00:00+00') TO ('2026-10-01 00:00:00+00');

CREATE TABLE audit_logs_y2026m10 PARTITION OF audit_logs
  FOR VALUES FROM ('2026-10-01 00:00:00+00') TO ('2026-11-01 00:00:00+00');

CREATE INDEX idx_audit_logs_org_created ON audit_logs(organization_id, created_at DESC);
CREATE INDEX idx_audit_logs_request ON audit_logs(request_id) WHERE request_id IS NOT NULL;
```
